# 미디어 SCM

홈쇼핑 방송 입력, PPL 계약·배분, 방송결과, 팀장 검토와 Google Sheets 연동.

## 배포 대상

- GitHub: `miheeshin110-a11y/media-scm` (private)
- Vercel: `miheeshin110-a11ys-projects/media-scm`
- 현재 코드는 이전 준비본입니다. 운영 데이터 이전과 외부 인증 설정을 완료한 뒤 실무 테스트를 진행합니다.

## 실행

Node.js 22 이상에서 `npm ci`, `npm run dev`를 실행합니다. 로컬 주소는 http://localhost:3100 입니다.
`.env.example`을 `.env.local`로 복사하고 각 환경의 값을 설정합니다. 비밀키 파일은 저장소에 넣지 않습니다.

## Google 로그인

Google Cloud에서 웹 애플리케이션용 OAuth 클라이언트를 생성합니다. 로그인 앱은 OpenID, 이메일, 프로필만 요청합니다.
운영 승인 리디렉션 URI는 `https://<확정된 운영 도메인>/api/auth/callback/google`입니다.
로컬은 `http://localhost:3100/api/auth/callback/google`을 사용합니다.

- `NEXTAUTH_URL`: 해당 환경의 확정된 URL
- `NEXTAUTH_SECRET`: 충분히 긴 임의의 서버 비밀값
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`: 로그인 OAuth 클라이언트
- `SCM_REVIEWER_EMAILS`: 관리자 이메일 JSON 배열
- `SCM_INPUTTER_EMAILS`: 입력 담당자 이메일 JSON 배열

인증된 Google 이메일만 허용 목록과 비교합니다. 등록되지 않은 계정은 접근할 수 없습니다.
이전 서비스의 `oai-authenticated-*` 요청 헤더는 새 서버에서 인증에 사용하지 않습니다.
입력 담당자와 관리자는 방송 입력, PPL 등록·배분을 처리할 수 있습니다. 검토 완료와 세금계산서 대조는 관리자 권한을 유지합니다.

## PPL 등록·배분 및 방송일 기준 (2026-10-21)

- 프로그램·거래처·총금액과 거래 방식(직거래/대행)을 입력한 뒤 본방·재방 송출일정을 함께 저장합니다.
- 대행료는 부가세 별도 총금액에 포함됩니다. 총금액 1,000만원, 대행료율 10%이면 대행료 100만원과 나머지 900만원이며, 배분할 총액은 1,000만원입니다. 직거래 대행료는 0원입니다. 원 미만은 버립니다.
- 홈쇼핑 방송에 등록된 송출회차를 선택하고 금액을 배분합니다. 송출일정 ID를 보존하므로 날짜를 변경해도 기존 배분금액은 유지됩니다. 연결 중인 일정은 삭제할 수 없습니다.
- 새 홈쇼핑 방송과 새 PPL 일정은 실제 날짜와 00:00~23:59로 입력합니다. 기존 24시 이상 표기와 캘린더 표시월은 일괄 변경하지 않습니다.
- BEP는 2026-10-22 확인에 따라 메인구성 100%와 메인 계획 예상 전환율로 계산합니다. 서브 판매조건·실적·사은품을 섞지 않으며 기존 수량·결과를 수정하지 않습니다. 방송비용 및 손익·검토 화면에 최소 주문수량과 VAT 포함/제외 주문금액을 표시합니다. 입력된 수량·금액 처리 기준으로 실제 손익 함수와 대조합니다.
- 비용 빈칸·미정 PPL은 미입력으로 표시합니다. 배송 건수를 별도 입력하는 방송은 BEP용 변동 배송비 기준이 없어 산출하지 않습니다. 전환율 0% 또는 출고당 마진 0원 이하는 고정비 회수 불가로 표시합니다. 시트 전송 시 기존 SCM_계산기준 탭에 BEP 결과를 덧붙이며, 구글시트 재연결은 별도 작업입니다.

## 목표·수량 계획 금액

- 목표·수량 화면에서 메인·서브 계획 주문수량과 예상 전환율을 입력하면 VAT 포함/제외 계획 주문금액, 계획 예상출고, 예상 공급매출, 총비용, 예상이익을 표시합니다.
- 주문금액은 계획 주문수량 × 판매가이며 전환율·수수료를 차감하지 않습니다. 예상 공급매출은 계획 예상출고 × VAT 제외 수수료 반영 공급단가입니다.
- 계획 계산은 방송에 저장한 구성·원가·방송비용·PPL 배분을 사용합니다. 방송결과의 주문수량·전환율·비용을 누락된 계획값 대신 사용하지 않습니다.
- 원가·비용이 없으면 주문금액과 공급매출 중 계산 가능한 값만 표시하고, 이익은 미산출로 남깁니다. 주문금액·공급매출은 금액 기준 미선택 시 반올림하며, 이익은 명시적인 금액 처리 기준까지 입력해야 산출합니다.
- 기존 직접 입력 목표금액과 저장된 방송결과·이익금은 계획 표시값으로 덮어쓰지 않습니다.

## 방송결과 시작 정보와 신규 사은품

- 방송결과의 시작일·시작시간 중복 입력은 제거하고 방송 기본정보의 날짜·시간을 참조합니다. 24시 이상인 기존 편성 표기는 실제 날짜로 환산합니다. 과거에 저장한 실제 시작값이 있으면 그 기록을 보존해 사용합니다.
- 종료일·종료시간 입력은 유지하며 시작보다 이른 종료는 저장할 수 없습니다. 기존 실제 시작 필드는 삭제하지 않고, 시트 출력은 새 결과의 시작값이 비어 있을 때만 등록된 방송 시작을 참조합니다.
- 사은품 아이템 선택 목록에 신규 사은품 등록을 추가했습니다. 등록한 이름은 다른 방송에서도 선택할 수 있고, 공백·대소문자와 확인된 약칭으로 인한 중복은 막습니다. 등록 이력은 공통 자료의 변경 이력에 남깁니다.
- 사은품 이름을 등록하는 작업은 단위원가를 생성하거나 기존 방송을 변경하지 않습니다. 다른 사은품으로 선택을 바꾸면 이전 단위원가를 비워 잘못된 원가 적용을 막습니다. 원가는 직접 입력하거나 원가 이력에서 선택합니다.

## 상품·사은품 원가 이력

- 초기 등록은 탭 상단의 엑셀 양식을 받아 담당부서가 「원가입력」 시트에 작성한 뒤 업로드합니다. 구분, 품목명, 단위, 적용 시작일, VAT 제외 단위원가 5개 열이며 작성 예시는 별도 안내 시트에 있습니다.
- 한 번에 XLSX 5MB·1,000행까지 읽어 등록 전 신규·중복·오류를 확인합니다. 같은 구분·품목명·단위·적용 시작일·원가는 건너뛰고, 금액 충돌이나 오류가 하나라도 있으면 전체를 저장하지 않습니다. 서버에서도 다시 검증하며 일괄 등록은 팀장 권한이 필요합니다.
- 별도 원가 이력 탭에서 상품/사은품별 품목명, 단위, 적용 시작일, VAT 제외 단위원가를 등록합니다. 팀장이 등록하며 실무자는 조회·적용할 수 있습니다.
- 같은 품목의 원가는 날짜별로 추가하며 기존 이력은 덮어쓰지 않습니다. 같은 품목·적용 시작일의 중복 등록은 막습니다.
- 판매조건의 상품 원가 품목 또는 방송결과의 사은품 원가 품목을 선택하면, 원가 기준일 당일 또는 이전의 가장 최근 원가를 적용합니다. 최초 선택 시 기준일이 비어 있으면 방송일을 사용합니다. 세트당 수량은 등록 단위와 맞춰 입력합니다.
- 적용한 단가·기준일·원가 이력을 방송에 함께 보관합니다. 마스터 추가나 단순 조회로 기존 방송 원가·이익을 변경하지 않습니다. 기준일 변경 또는 명시적인 다시 적용 때만 새 원가를 선택합니다.
- 기존 수동 원가는 그대로 유지합니다. 자동계산이 꺼진 기존 방송의 저장 이익도 보존하며, 이익 자동계산은 기존 자동계산 옵션을 켠 방송에 적용합니다.
- 기준일에 맞는 원가가 없으면 미등록으로 표시하고 이익을 미산출로 남깁니다. 0원으로 등록한 원가와 미등록을 구분합니다.
- 원가 이력은 기존 공통 자료의 JSON과 변경 이력에 저장하므로 DB 스키마 변경이 없습니다. 이력 등록만으로 방송 재저장이나 구글시트 전송을 요청하지 않습니다.

## 저장소

Neon PostgreSQL을 사용합니다. Vercel에서 SCM 전용 Neon 저장소를 연결하고 `DATABASE_URL`을 Production 비밀 환경 변수로 설정합니다.
Preview는 별도 테스트 DB를 연결하기 전까지 운영 DB에 접근하지 않습니다.

환경 변수를 로드한 상태에서 `npm run db:migrate`로 테이블을 만듭니다.
Vercel Production 배포에서는 빌드 전에 같은 마이그레이션을 자동 실행합니다. Preview 빌드는 실행하지 않습니다.
마이그레이션 이력과 체크섬을 검증하며 실패하면 전체 트랜잭션을 롤백합니다.
기존 테이블이 있는데 이력이 없다면 자동 덮어쓰지 않고 중단합니다.
방송 버전, 변경 이력, 전송 대기는 동일 쓰기 트랜잭션으로 저장됩니다.
방송과 계약의 동시 수정은 공통 트랜잭션 잠금과 버전 비교로 보호합니다.
시트 전송 중에는 저장 트랜잭션을 유지하지 않습니다.

## Google Sheets

`GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`는 서버 환경 변수에만 등록합니다.
로그인 OAuth 비밀값과 별개입니다. 기존 테스트 시트는 `lib/sheet-mapping.ts`에 지정되어 있습니다.
기존 서비스와 새 서비스가 같은 행을 동시에 수정하지 않도록 데이터 이전 전에는 새 서비스에 시트 키를 등록하지 않습니다.

## 전환 순서

1. 별도 저장소 및 OAuth 설정 완료
2. 기존 서비스 입력 중단 시점 확정 후 원본 DB 백업
3. 방송 row_id, version 및 계약·배분·변경 이력·전송 상태를 보존하여 빈 대상 DB로 이전
4. 시트 행 번호와 비용배분 합계 대조
5. 기존 서비스 쓰기 중단 확인 후 새 서비스에 시트 키 등록
6. 관리자/실무자 로그인, 부분 저장, 팀장 검토, 계약 배분, 시트 반영 검증

`SCM_SEED_RECORDS`는 기본적으로 꺼져 있습니다. 이전에 사용한 데모 샘플을 운영 데이터처럼 자동 등록하지 않습니다.

## 검증

`npm test`와 `npm run build`를 실행합니다. 업무 계산·배분, Google 계정 허용 목록, PostgreSQL 트랜잭션을 검증합니다. 저장 테스트는 PGlite의 실제 PostgreSQL 엔진에서 운영 SQL을 실행합니다. 원격 Neon 연결 검증은 별도 진행합니다.

## 상품·사은품 원가 자동 적용

사은품을 새로 추가하거나 이름을 선택하면 방송일 기준으로 사은품 원가 이력을 자동 적용합니다. 기존 방송의 변경하지 않은 사은품 원가·스냅샷은 날짜나 마스터 이력이 바뀌어도 유지합니다. 사은품명을 명시적으로 바꾸면 해당 행의 이전 원가를 해제하고 새 품목을 적용합니다. 이력이 없거나 여러 단위가 충돌하면 원가는 미입력으로 남으며, 상품 원가를 대신 사용하지 않습니다.

새 방송에서 표준 아이템을 선택하면 상품 원가 이력의 표준명·별칭과 연결해 방송일 당일 또는 이전에 시작하는 최신 원가를 메인·서브 구성에 적용합니다. 최초 저장 시에도 같은 규칙을 서버에서 적용합니다. 저장 전 방송일 변경은 자동 원가를 갱신하지만, 기존 방송과 수동 원가·명시적으로 선택한 다른 원가 이력은 유지합니다. 원가 이력이 없거나 단위가 여러 개여서 품목을 확정할 수 없으면 0원으로 추정하지 않으며, 판매조건에서 품목을 직접 선택해야 합니다.

## 물류 SCM · 기존 앱 확장

기존 앱의 `물류 SCM` 메뉴에서 준비현황, 품목·구성, 재고·입고, 부족예측, 변경이력을 관리합니다. 별도 사이트·프로젝트·DB를 만들지 않으며 `scm_finance`의 물류 자료와 기존 변경 이력·버전 충돌 방지 기능을 사용합니다. 물류 등록은 방송 레코드, 원가·이익, 방송 변경 이력 및 Sheets 전송 대기열을 수정하지 않습니다. 등록된 회사 운영자는 물류 작업이 가능하며 기존 로그인·요청 출처 검사를 그대로 적용합니다.

- 판매구성 코드에 **본품과 사은품 전체**의 물류 상품코드·세트당 EA 수량을 매핑합니다. 방송 요청 세트수 전량을 적용하고 전환율을 곱하지 않습니다. 방송결과 사은품은 구성표에 포함된 사은품과 중복 합산하지 않습니다. 구성표 확인은 전달 확정 시 필수입니다.
- 작성 중 변경은 물류에 전달되지 않습니다. 명시적 전달 확정으로 방송별 버전을 생성하고, SCM 확인·준비 상태·담당자·메모를 남깁니다. 일정·구성·요청수량 변경 뒤에는 새 버전을 전달해야 확인할 수 있습니다. 과거 확정 계획과 처리 이력은 보관합니다.
- 재고는 EA 기준 창고별 전체 스냅샷이며 미등록 품목은 재고 미확인입니다. WMS 재고가 이번 계획의 예약 차감 전/후인지 확인합니다. 차감 후라면 이번 예측 대상 계획에 대해 이미 차감된 예약수량만 입력해 복원합니다. 타 주문 예약·불량·격리 수량과 혼합하지 않습니다.
- 확정 입고의 미입고 잔량만 준비기한(방송 7일 전)까지 반영하며, 재고 기준일 당일·이전 입고는 다시 더하지 않습니다. 입고 완료·예약·실제 출고를 WMS에 자동 기록하지 않는 **계획 예측**입니다. 신규 재고 스냅샷과 입고 잔량을 담당자가 갱신해야 합니다.
- 최신 전달 계획을 창고별·방송일 순으로 합산하고, 본품·사은품에 동일한 물류 상품코드를 쓰면 한 재고에서 차감합니다. 미전달 변경·취소는 이전 확정 수량을 유지하고, 취소 전달 확정 후 해제합니다. 부족수량은 누적 부족이므로 행별 합산하지 않습니다.
- 품목·구성표·재고·입고는 화면의 CSV 양식을 내려받아 XLSX/CSV로 업로드할 수 있습니다. 첫 시트, 정확한 제목, 최대 1,000행·5MB를 사용하며 미리보기 후 저장합니다. 실제 WMS 원본 파일의 열 자동 매핑과 API·슬랙 자동연동은 포함하지 않습니다.

운영 도입 전 실제 수량계획/재고/WMS 자료의 상품코드, EA 환산, 가용재고 정의 및 예약 차감 범위를 담당자와 확정해야 합니다. 테스트는 임시 PGlite 데이터만 사용합니다.

## PPL 원본 계약과 방송별 배분 추적

계약서·이체 확인의 기준은 `SCM_계약`의 원본 계약 총액입니다. 방송별 배분은 이 총액을 변경하지 않으며 방송 원가·이익에는 각 배분금액만 적용합니다. 공급가액·부가세·합계금액은 각각 구분합니다.

`SCM_방송배분`은 기존 계약ID·배분ID를 유지하고 마지막 열에 `원본 PPL별 배분코드`를 전송합니다. 예: 원본 `PPL-2026-0001`, 배분 `PPL-2026-0001-000001` / `PPL-2026-0001-000002`. 뒤 번호는 전체 배분의 고유번호이므로 계약 내 연속번호일 필요는 없습니다. 금액 수정·입력 순서 변경·배분 해제에도 같은 배분의 코드를 유지하고 해제 번호를 재사용하지 않습니다. 해제 내역은 상태가 `해제`로 남으므로 배분금액 집계 시 `유효`만 합산해야 합니다. 원본 계약금액과 배분금액을 함께 더하지 않습니다.
