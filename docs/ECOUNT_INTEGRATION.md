# 이카운트 재고 조회 연결

## 업무 기준

- 운영용 API, 이카운트 창고 **샌드부스터 / 200**.
- B열 V코드는 이카운트 품목코드와 동일합니다. D열 세트 재고는 차감하지 않습니다.
- 예약·출고대기 차감 전 현재고로 받습니다. 자동 예약·전표·출고 입력을 하지 않습니다.
- 유기농 홍화씨 V00100110 및 보류된 세트는 제외합니다.
- 이카운트 일괄 재고 API는 품목 단위를 반환하지 않습니다. 담당자가 SCM 구성수량표와 실제 이카운트 품목 단위가 같은지 확인한 뒤 반영해야 합니다. 불량·격리 등 출고 불가 물량도 실무 기준과 대조하세요.

## 서버 환경변수

기존 Vercel `media-scm`의 Production에 등록한 다음 항목을 사용합니다. 값은 브라우저·로그·채팅으로 출력하지 않습니다. 새 키나 프로젝트를 만들지 않습니다.

- `ECOUNT_COMPANY_CODE`: 회사코드
- `ECOUNT_USER_ID`: 운영용 API 인증키 사용자
- `ECOUNT_API_CERT_KEY`: 운영용 인증키
- `ECOUNT_WAREHOUSES`: `[{"code":"200","name":"샌드부스터"}]`

ZONE은 회사코드로 매번 새 조회 시 자동 확인하므로 `ECOUNT_ZONE`은 필요 없습니다. 변수명은 `COUNT_WAREHOUSES`가 아닌 **ECOUNT_WAREHOUSES**입니다.

## 사용 방법

1. 물류 SCM → **이카운트 재고 불러오기**.
2. 샌드부스터(200)의 V코드별 현재고·조회 기준일·조회시각을 확인합니다. 10분 이내 같은 조회는 저장된 결과를 재사용합니다.
3. 수량 단위와 현재고 기준 확인 체크 후 **확인한 재고만 SCM에 반영**.
4. 이 창고의 SCM 재고가 새 조회 자료로 교체됩니다. 미조회 품목은 0이 아니라 미확인입니다. 기존 스냅샷은 이력으로 남습니다. 일부 품목만 조회된 경우 반드시 미확인 목록을 확인하세요.
5. 방송 필요수량과 부족분을 확인하고 실제 준비 완료는 별도로 기록합니다. 이미 입고된 예정 잔량은 중복 계산되지 않도록 물류팀이 확인합니다.

조회는 준비 결과 캐시에만 저장하며, 담당자의 반영 전에는 SCM 재고·방송·원가·이익을 변경하지 않습니다. 반영은 기존 finance 버전 검사와 물류 전용 저장을 사용하며 방송 결과·PPL 비용을 수정하지 않습니다. 재고 반영 후 기존 물류 구글시트 작업만 예약합니다.

## API 및 보호 처리

2026-11-10, 사용자가 열어 둔 이카운트 공식 API 매뉴얼의 Zone / 로그인 / 창고별재고현황 규격을 직접 확인했습니다. 인증 요청은 운영 호스트만 사용하며 지정 창고 이외의 응답은 반영하지 않습니다.

- Zone → 로그인 → 창고별재고현황 조회. 자동 재시도 없음.
- `ZERO_FLAG=Y`: 명시적으로 조회된 0만 0으로 처리.
- 외부 오류·인증키·SESSION_ID·원본 응답·요청 URL은 출력하지 않습니다. 세션은 메모리 내에서만 사용하고 저장하지 않습니다.
- PostgreSQL의 별도 `scm_ecount_cache` 한 행으로 배포 인스턴스·사용자 사이 조회 제한과 캐시를 공유합니다. 최초 호출 시 해당 캐시 테이블만 idempotent하게 생성합니다. 기존 운영 테이블을 마이그레이션하지 않습니다.
- 일반 조회 10분 제한 / 인증 실패 1시간 대기 / 같은 인증정보로 3회 실패하면 인증 설정 변경 전까지 호출 중단. 환경변수를 바꾸지 않은 단순 재배포로 제한이 초기화되지 않습니다.
- 모든 요청은 로그인 및 동일 출처 검사. 키는 클라이언트에 전달하지 않습니다.
- 제한 시간·최대 응답 크기·수량 정수 검증·중복/다른 창고/누락 응답 검사.
- 반영은 10분 이내 조회 결과만 사용. 구성 단위·코드 또는 창고 연결이 바뀌면 재확인 필요. 동시 방송 입력은 수정하지 않으며 finance 저장 충돌 시 최신 자료로 다시 확인합니다.

## 운영 확인

실제 API 인증은 서버에 등록된 키로 배포 후 첫 조회 시 확인합니다. 키를 로컬로 내려받지 않습니다. 허용 IP 오류가 있으면 이카운트 API인증키발급의 IP등록과 현재 서버 출발 IP 정책을 확인하고 제한을 임의 해제하지 않습니다. 오류 메시지에는 원본 IP/인증 값이 포함되지 않습니다.

배포 전 검증은 임시 응답과 임시 PostgreSQL로 수행합니다. 이 테스트는 운영 인증 성공 또는 실제 수량 일치까지 검증한 것을 뜻하지 않습니다.
